# 修复全书收束、紧张度曲线与导演跟进历史项

## Goal

让新手把“我设了多少章”理解成一本写得完的书：目标章数到达时能看见收束，节奏板上的紧张度能反映张弛，导演跟进只把当前要处理的问题顶在角标上。

这是父任务。它只负责三条独立缺口的需求对齐、子任务边界和交叉验收；不直接改产品代码。

## User Value

当前新手会遇到三件互相独立、但都会破坏“写完整本小说”的体验：

1. 设 150 章写到最后，不像结局，也不像明确的小结局。
2. 节奏/拆章页的紧张度曲线几乎是一条平线，看不出节奏段在变化。
3. 导演跟进堆着历史问题，页面上关不掉，侧栏红角标一直在。

## Confirmed Facts

### 1. 目标章数收束

- `buildDirectorCompletionProfile()`：目标 ≤ 60 章走 `compact_book`（全书结局合同 + 最多再加 5 章只用于收束）；目标 ≥ 61 章走 `serial_book`（前 30 章承诺、分阶段续写）。
- `isCompactBookFinaleBeat()` 只对 `compact_book` 为真。150 章的最后一拍不会进入终章合同。
- 卷骨架只在紧凑全书时把最后一卷写成终局卷；连载路径的 `nextVolumeHook` / 节奏板 `end_hook` / 拆章末章都要求留下下一阶段牵引。
- 写作侧 `buildNarrativeProgressHint()` 在进度 ≥ 90% 时提示“尾声、收束所有主线”，与连载“必须留钩子”指令互相打架。
- 紧凑全书才有 `novel.compact_book.structure@v1` 和 `novel.compact_book.ending_audit@v1`。连载没有对等的目标跨度收束合同。
- 用户可接受两种结果：第 150 章写成结尾，或把这 150 章做成看得见的小结局。二者都比“最后一章只留钩子”更符合新手完本预期。

### 2. 紧张度曲线

- 节奏/拆章曲线的数据源是 `VolumeChapterPlan.conflictLevel`，量纲 0–100，不是正文情绪分析。
- 拆章 schema 每章只允许 `title` / `summary` / `beatKey`，明确禁止额外字段；拆章阶段不生成冲突强度。
- 缺值复用路径会落到 `conflictLevel ?? 3`。在 0–100 尺子上，3 接近底部；曲线分析把相邻章差值 ≤ 3 判成“节奏平坝”。
- 用户锚定（`conflictLevelSource = "user"`）必须保留。参考线（升级流/悬疑流）只是对照，不会写入规划。
- 冲突强度目前主要服务规划展示和章节细化合同；写作上下文虽拷贝该字段，分层写作 prompt 没有把它当成节奏约束。

### 3. 导演跟进历史项

- 导演跟进会投影取消、已替代、自动通过等历史项。
- 侧栏角标直接使用 `overview.totalCount`，历史项也计入红点。
- 跟进页没有关闭/归档动作。小说工作区已有 `archiveTask("novel_workflow", id)`（“从任务列表移除”/“完成并收起”），归档后跟进查询会排除该 id。
- 运行记录（任务中心）是只读面，不能放取消、归档、恢复等变更动作。导演跟进是自动导演问题的源页面，关闭入口应放在这里。
- 已有任务 `09-06-director-badge-semantics` 修的是进度风险徽标（需复核/缺少规划资源），覆盖不了跟进列表和侧栏角标。

## Child Task Map

| 子任务 | 用户结果 | 独立验收 |
| --- | --- | --- |
| `09-08-serial-book-ending-contract` | 目标章数到达时出现可见收束或小结局 | 新规划的连载书在目标章看到收束；紧凑全书原合同不变 |
| `09-08-chapter-list-conflict-curve` | 拆章后紧张度曲线有节拍起伏，且能约束后续细化/写作 | 新拆章不再全是 3 附近的平线；用户锚定不被覆盖 |
| `09-08-follow-up-history-dismiss` | 历史跟进项可收起，角标只统计当前待处理 | 收起后列表和角标同步下降；进行中的阻塞项不能被收起 |

三条链路无实现依赖，可并行；合并进 `beta` 前由本父任务做一次交叉验收。

## Requirements

1. 不把 61+ 章书改成 `compact_book`。150 章仍走连载分卷/分拍，但目标章必须形成**可见小结局**，而不是继续只留必须续写的新主线。
2. 紧张度曲线必须在拆章阶段就有 0–100 的节拍起伏，并沿细化、执行合同、写作上下文传递；禁止再用默认 3 把曲线压平。
3. 导演跟进必须能收起历史项；侧栏角标只统计当前待处理。收起复用已有任务归档，不在运行记录里做变更。
4. 自动导演完成优先规则不变：局部质量问题记质量债并继续；不能因为小结局审校或曲线形状把全书链打成失败。
5. 不自动重写已保存正文。已有 150 章书通过重规划/重拆章/重算曲线/收起跟进项生效。
6. 本父任务不改产品代码。实现落在三个子任务；工作区里与本主题无关的已有改动不得带入提交。

## Acceptance Criteria

- [ ] 三个子任务各自的验收标准全部通过。
- [ ] 紧凑全书（≤60 章）的结局合同、最多 +5 章收束预算、完本检查语义保持不变。
- [ ] 61+ 章书到达 `endingRequiredBy`（即用户设定目标章数）时，最后一卷/最后一拍/目标章不再被指令要求“必须留下下一阶段新主线”。
- [ ] 新拆章的冲突强度落在 0–100，同卷相邻章可以看到节拍起伏；用户锚定章保持原值。
- [ ] 导演跟进收起历史项后，该条从跟进列表消失，侧栏角标下降；失败待恢复、等待确认、运行中的项不能被收起成历史。
- [ ] 运行记录仍只读；关闭动作只出现在导演跟进或小说工作区这些源页面。

## Out of Scope

- 把 `compact_book` 阈值从 60 提到 150。
- 给 150 章连载套用紧凑全书的强制完本审校，并据此暂停自动导演。
- 回写或重写用户已保存的章节正文。
- 任务中心（运行记录）增加取消/归档/恢复按钮。
- 现有导演进度风险徽标任务（需复核/缺少规划资源）。
- 把紧张度改成对正文做事后情绪分析；第一期仍以规划字段为准。

## Key Decisions

1. **连载目标章 = 可见小结局，不是紧凑全书完本。** 主冲突本阶段兑现、高潮可见、可留余味；禁止只留必须续写的新主线。这同时覆盖用户说的“结尾”和“本次 150 章算小结局”。
2. **曲线先有规划数字，再约束写作。** 拆章生成 `conflictLevel`；细化可调整但不得覆盖用户锚定；写作上下文必须读到该强度。
3. **跟进历史用已有归档，不新造取消状态机。** 角标改成待处理计数，不把 `totalCount` 当红点。

## Risks

- 已写到 150 章的旧书不会自动出现结局；需要重跑收官卷/最后一拍或接受“只对后续生成生效”。
- 拆章 JSON 增加 `conflictLevel` 后，旧测试和“每章只能三个字段”的 prompt 约束必须一起改，否则结构化输出会失败。
- 跟进角标改口径后，进行中的自动推进是否计入红点要在子任务里写死，避免“没问题也有红点”或“真阻塞没有红点”。
