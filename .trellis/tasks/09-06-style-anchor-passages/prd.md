# 范文锚点回流与生成注入

## Goal

当前风格指导全部是抽象文字（节奏、信息密度、句式组织……），模型对抽象词的执行远弱于对具体文本的模仿。本任务建立「范文段落」资产：把用户认可的具体段落采集下来，在章节生成时作为风格锚点注入，让风格从「形容词描述」升级为「正样本模仿」，并形成「多候选改写 → 用户采纳 → 回流为范文」的正反馈闭环。

## Requirements

### 范文采集（低认知负担，不新增必做步骤）

- 采集来源一（核心）：章节编辑器采纳改写候选时，把被采纳文本自动回流为范文段落，来源标记为 `adopted`。
- 采集来源二（补充）：章节编辑器提供「标记为范文」的手动入口，用户选中正文片段即可标记，来源标记为 `manual`。
- 采集动作对用户零认知负担：采纳回流完全自动、不弹窗打断；手动标记是编辑器内一键操作。
- 采集失败（网络、服务异常）静默处理，绝不影响章节保存与编辑器主流程。

### 范文资产（本书作用域）

- 范文段落持久化为小说作用域资产：原文（截断上限约 800 字）、来源章节、来源方式、创建时间；同一文本去重；单书数量设上限防膨胀。
- 只收用户显式采纳/标记的文本，不做 AI 自动判定「写得好」自动采集（质量门槛由用户确认保证）。
- 提供查看与删除入口（管理 UI 保持最小，可在编辑器或写法设置内承载）。

### 生成注入

- 章节生成时注入 1-2 段范文（总预算几百字），作为新上下文组 `style_anchor_passages`；选择策略在 design.md 定夺（倾向轻量确定性选择，避免动 RAG 索引链；语义检索留作后续增强）。
- 新书冷启动：用户确认范文为空且本书写法资产来自拆书分析时，允许以拆书源文本的代表性叙事段落作为初始锚点降级注入（源文本经知识文档链路已可检索），不依赖任何用户动作；纯简介生成的写法资产无源文本，该层自然缺省。
- `novel.chapter.writer` 版本升级：style contract 区块追加范文锚点说明——句式与节奏以此为参照，模仿其具体性与细节密度；禁止照抄范文中的具体情节、人物、地名等实体（沿用写法资产 sanitize 的防串味思路；使用拆书源文本做初始锚点时，必须同步注入 sanitize 产出的 forbiddenEntities 清单与「仿写法不仿实体」约束，防止向源作品贴脸）。
- 新上下文组按 contextPolicy 管理（preferredGroups + dropOrder 尾部），不挤掉 required 组。

### 非阻塞与降级

- 无范文、检索失败、服务异常时：静默不注入该区块，章节生成正常完成（符合完成优先与非阻塞规则）。
- 存量书籍（无范文）生成链路行为与现状一致。

## Acceptance Criteria

- [ ] 采纳改写候选后，范文库出现该段落（来源 adopted、去重生效）；再次采纳相同文本不重复入库。
- [ ] 手动标记选中片段可入库并可删除。
- [ ] 有范文的书：生成上下文出现 `style_anchor_passages` 区块；writer 提示词包含锚点说明与防照抄约束。
- [ ] 冷启动：有拆书写法资产、无用户范文的新书能注入初始锚点（源文本可检索时），且锚点区块携带实体护栏；无写法资产的书无区块且生成正常。
- [ ] 无范文、服务异常场景：生成链路正常完成，无空区块、无报错。
- [ ] 存量书回归：生成链路无报错。
- [ ] typecheck 通过；服务层单测覆盖入库去重、注入选择、降级路径。

## Out of Scope

- 不做跨书共享范文或范文市场。
- 不做 AI 自动采集/自动评分范文。
- 不改写法资产（style profile）提取与净化机制本身。
- 不动 RAG 索引 worker 与向量库链路（如 design 选用独立轻量存储）。
- 范文管理不做复杂标签体系（章节来源 + 来源方式足够）。
