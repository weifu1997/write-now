# 种子章节评测协议

> 目的：四个子任务都是提示词/链路层改动，必须有「改前改后」的实测对比才能判断哪项真起作用（父任务验收项）。本协议在**第一个子任务合并进 beta 之前**执行 baseline 留档。

## 种子选取

从用户现有书籍中选定 1 本 + 3 章，覆盖三种节奏类型（对应计划字段的节奏判断设计）：

| 编号 | 类型 | 选取标准 |
| --- | --- | --- |
| S1 | 推进章 | 有明确任务推进与冲突的常规章节 |
| S2 | 转折章 | 含反转、升级或重大决策的章节 |
| S3 | 缓冲章 | 节奏放缓、以关系或日常为主的章节 |

选取后把书名、章节序号记录到本文件下方表格，后续所有对比固定用同一批章节。

## 统一参数（对照变量控制）

- provider / model / temperature：使用生成当时的链路默认值，**不手动调参**；执行时把实际值记录到下表。
- 上下文：同一章节在同一本书状态下生成（避免生成过程中书状态变化导致上下文漂移；如需重生成，恢复到相同存档点）。
- 模型与采样参数在整个任务树期间保持不变；中途换模型须重新采集 baseline。

## 留档内容与路径

每次生成留档一个 JSON 文件，路径：`.trellis/tasks/09-06-de-ai-flavor-prose/seeds/<baseline|after>/<S编号>.json`（`seeds/` 目录加入 .gitignore，正文内容不进 git；本文件记录文件名与摘要即可）。

每个文件记录：

- `meta`：种子编号、生成时间、git 提交哈希、provider/model/temperature、styleProfileId。
- `content`：生成的章节正文全文。
- `review`：审校 JSON（score + issues）。

## 执行时机

1. **baseline（改前）**：第一个 feature 分支合并进 beta 之前，用当时的 beta 代码各生成一次 S1-S3 并留档。
2. **after（改后）**：四个子任务全部合并进 beta 后，同一参数重新生成并留档。
3. **盲评**：把 baseline 与 after 的正文去除标识后随机排序，由用户盲评（哪版更像人写的、哪版更愿意往下读），对比结论回写本文件并记入各子任务收尾。

## baseline 采集方式（任务1-3 已合并进 beta 后的修正）

任务 1-3 已于 2026-09-06 合并进 beta（b951134c）。「改前」状态可用以下任一方式留档：

1. **运行中的旧实例（推荐）**：如果当前部署/运行的实例还没更新到最新 beta，直接在旧实例上对种子章节各生成一次并留档，记录当时版本号或提交哈希。
2. **旧提交生成**：`git worktree add /tmp/write-now-baseline ad30a388`（任务 1 合并前的 beta），在该目录启动应用后生成留档；用后 `git worktree remove` 清理。
3. 若两条路都不可行，降级方案：用最新 beta 生成 baseline，并在盲评结论中注明「改前」包含任务 1-3 的效果（对比结论只反映任务 4 的边际贡献）。

无论哪种方式，meta 里必须记录生成时的 git 提交哈希，保证可追溯。
