# PRD：站点登录门禁

## Goal

把项目部署到服务器后，未登录的人不能进入产品，也不能调用业务接口。这是单实例站点门禁，用来挡住公网访问，不是多用户账号系统。

## Background

产品按本机/桌面单实例设计：小说、模型密钥、设置都在同一份数据库里，没有用户表，也没有数据归属字段。

后端 `server/src/middleware/auth.ts` 目前直接放行。部分路由挂了这个中间件，但短剧、漫画、市场雷达、自动导演主路由、LLM 实况流等没有挂。Docker 健康检查和前端启动探测都依赖公开的 `/api/health`。前端 axios / `fetch` / SSE 目前都不带 cookie。

Docker 整栈已经可以部署，默认打开 `http://服务器:8080` 即可使用。桌面端打包进程会把 `NODE_ENV` 设为 `production`，同时带 `AI_NOVEL_RUNTIME=desktop`，因此不能只用 `NODE_ENV=production` 判断是否必须登录。

## Requirements

- R1. 站点开启门禁后，未登录访问前端业务页必须进入登录页，不能看到小说、设置、密钥等内容。
- R2. 站点开启门禁后，未登录调用业务 API 必须被拒绝；不能只挡页面、不挡接口。短剧、漫画、市场雷达、自动导演、LLM 实况流等现有漏挂鉴权的接口也必须挡住。
- R3. 登录成功后，同一浏览器可继续使用现有全部功能，体验与现在单实例一致。
- R4. 提供退出登录。退出后再次访问必须重新登录。
- R5. `/api/health` 在门禁开启时仍可匿名访问，避免 Docker 健康检查和本机启动探测被挡。
- R6. 凭证属于部署配置，通过环境变量提供用户名和密码；不进设置面板，不在页面展示明文密码。
- R7. 本机开发与桌面端在未要求站点门禁时，保持现有免登录行为。
- R8. 服务器/Docker 部署默认要求门禁。未配置用户名或密码时，除健康检查和鉴权状态查询外拒绝访问，并提示去配置环境变量；不得在未配置时继续开放工作台。
- R9. Docker/部署文档说明如何开启门禁、如何设置账号密码。compose 不内置默认密码。
- R10. 钉钉/企微等自动导演频道回调继续使用既有通道令牌校验，不要求浏览器登录 cookie。

## Out of Scope

- 多用户注册、权限角色、按用户隔离小说/密钥/设置。
- OAuth、SSO、邮箱验证、验证码、找回密码。
- 在产品设置页改密码或管理账号。
- 给 Nginx 单独加 basic auth 作为唯一方案。
- 改造桌面端为必须登录。
- HTTPS 证书申请与反向代理改造。登录 cookie 在 HTTPS 下自动加 Secure，当前 HTTP 部署仍可用。

## Acceptance Criteria

- [ ] 服务器/Docker 未配置站点用户名或密码时，打开站点看不到工作台，业务 API 被拒绝；`/api/health` 仍可访问。
- [ ] 配置正确后，未登录打开站点会看到登录页，看不到工作台内容。
- [ ] 配置正确后，未登录直接请求业务 API（含现有漏挂鉴权的接口）会被拒绝。
- [ ] 使用正确用户名和密码可进入并正常使用现有功能，包括流式生成。
- [ ] 错误密码不能进入，也不能拿到业务数据。
- [ ] 退出登录后需要重新登录。
- [ ] 本机开发与桌面端未要求门禁时，仍可免登录使用。
- [ ] Docker/部署文档写明如何配置站点登录，且不提供可直接使用的默认密码。
